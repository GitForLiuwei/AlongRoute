## 2026-11-09：枢纽优先召回、批量粗排、出口分流补充

- 后续线上修复：真实规划在 `hub_seeds` 日志事件中把枢纽类型写入 `kind`，与搜索日志的请求类型字段冲突，触发 TypeError/HTTP500。现改为 `hub_kind`，同步回放字段，并让日志系统保留自身请求身份元数据，避免载荷冲突中断业务。新增通过HTTP、枢纽发现、日志及回放完整链路的回归测试；后端156项通过，前端类型检查及构建通过。

- 默认 `CANDIDATE_STRATEGY=hub_first`：围绕 A→B/A→C 与 C 的最多六个中心召回地铁、公交、停车场，使用 SQLite R-tree 候选池；几何/OSRM 预排最多96个种子，再展开最多12个枢纽的真实驾车接近路线，每个枢纽最多生成两个普通道路点。保留沿途普通道路，枢纽道路不足时才做最多八秒的出口分流补充。
- 新增 `coordinates.py`、`osrm.py`、`coarse_routing.py`、`hub_store.py`、`hub_discovery.py`。OSRM 由 `OSRM_BASE_URL` 可选配置，每批最多80个候选，以两张有向稀疏表取得 A→B、A→P、P→B、P→C；缺失、超时、字段不支持或吸附异常回退几何排序，不认定路线不可行。未部署或下载 OSRM 路网。
- 初始精算最多48个、普通道路最多预留12个，每批八个；完成至少24个且满足结果/方式/区域覆盖条件时可以提前结束。最终仍使用高德完整司机路线、绕行及费用硬上限、实际入口300米步行限制；保留原打车评分及公交偏好。
- 修正同一 P 不同司机路线被混合合并的风险，推荐 ID 包含候选约束身份；候选池与实时搜索重叠时先去重再分配种子名额。驾车缓存缩短为180秒、公交300秒，TTL策略参与缓存键使旧24小时条目失效。
- 回放新增枢纽种子、粗排来源与估算信息；更新 API、README 和配置示例。`CANDIDATE_STRATEGY=legacy` 保留旧流程作对照。枢纽召回受范围和POI页数限制，保持搜索不完整的说明。
- 验证：154项后端离线测试通过；前端 TypeScript 检查和 Vite 生产构建通过；差异空白检查通过。新增覆盖有向矩阵及索引、坐标转换、部分空值/吸附/超时、远离原线的枢纽召回、受限道路拒绝、本地池失效/去重、出口补充及不同到达路径不合并。

## 2026-11-05：打车双目标筛选

- 仅修改普通算法项目 AlongRoute，AlongRoute-LLM 不在本次改动范围。
- 打车先执行司机增加时间硬限制（完整途经路线相对基准的额外驾驶，加停靠），再以司机增加时间、打车预估费用两维淘汰被全面超过的候选。乘客共同乘车、接车缓冲、后续行程仍用于展示和到达估算，不参与打车排名，也不受旧版15分钟乘客耗时预算约束。

- 费用相同优先少绕路；费用未知或无效不能当作零，最短绕路的未知价方案只作为补充或后备，并明确标为待估价。打车分数仅表示短名单顺序。

## 高速出口与近站规则更新

- 仅公共交通选项有首乘实际站台/地铁入口步行≤300米的硬限制。只选打车不会调用公交规划；同时选择时，两种方式分别保留候选搜索名额，每个位置独立验证两种方式，公交失败不删除可用打车选项。
- 公交搜索增加车辆驶向站点的实际路线末端候选：公交站附近40/70/120米，地铁入口附近10/30/70米。距离是生成候选的偏移量，最终仍核验真实步行距离和驾车可达性，不把站台坐标直接视为可停靠点。
- 第一批成功方案出来后，再围绕方案实际使用的至多两个首乘站点补找更近位置。相同费用、换乘不增加、全程时间相差不超过2分钟且综合分接近时，优先实际到站步行更短的方案。
- 高速/快速路主线不再作为下客地点周边搜索中心；道路名称与导航说明共同识别受限路段，立交、匝道不直接作为停靠位置。
- 高速沿途分散搜索出口POI，同时提取原路线转入普通道路的区域。出口是发现区域的锚点，不作为下车点。优先原路线驶出区域，同时允许在用户耗时上限内提前驶出。
- 高速附近的下客候选需关联出口，完整请求A→驶向出口的沿途点→出口→P→B；检查途经顺序及P附近道路条件，额外时间包括后续驶向B和停靠，不能只计算驶出高速这一段。
- 出口发现与搜索仍有预算，不能保证覆盖所有出口；POI位置、道路侧和现场停靠条件仍需确认。没有出口或无法证明途经连接时，过滤该高速附近候选，不猜测出口可用性。
- 起点已在高速等受限路段时，不再把“从A立即换乘”当成可执行对照。

本轮真实接口验证：广州公交行程取得3个候选，首乘到站步行33米、41米、160米；以高速主线坐标为起点的高速打车行程取得2个有出口关联的候选，均无需公交站或300米接驳数据。验证只覆盖接口路线及约束，不代表现场停靠已核实。


## 公共交通详细乘坐方式

公共交通选项新增按行程顺序排列的 transit_steps：到首站步行、每段公交或地铁、换乘步行、末站到乘客目的地步行。每段乘车展示线路及区间标识、开往方向、上下车站、乘坐站数、途经站、已返回的进站口与出站口；步行展示距离、耗时和可展开指引。供应商只返回中间途经站数时，乘坐站数按该数字加一；缺失方向和站数时明确提示，不自行猜测。

首段步行的展示距离、耗时及指引与300米核验使用同一路径。独立步行核验替换原路径时清除旧路径指引。推荐面板切到“公交 / 地铁”后直接显示乘坐步骤，对照方案也可展开查看。打车面板不显示公交步骤，旧结果缺少新字段时提示重新计算。
