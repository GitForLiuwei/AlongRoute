# 实时地图、搜索日志与回放

## 高德底图

用户页和调试页的路线总览只使用高德底图，页面打开后即加载，规划期间保持同一个地图实例。页面不提供经纬度示意图或切换按钮。地图需要前端 JS API Key 和后端 JS 安全代理配置；加载失败显示重试入口，缺少配置时显示连接或配置提示。

## SSE 实时进度

1. 前端在 `POST /api/recommend` 前生成 32 位十六进制编号，并通过 `X-Search-ID` 请求头发送。
2. 用户页在计算期间打开 `GET /api/search-replay/{search_id}/stream`。连接先于 POST 到达时，后端预注册 Trace；晚于 POST 到达时，先发送已有事件快照，再推送新事件。
3. `candidate_generated` 驱动沿途选点；`candidate_started`、`candidate_accepted`、`candidate_rejected` 驱动核验高亮与路线。被淘汰候选显示约 260ms 核验状态后移除。
4. `search_finished` 后发送 `event: done`；断开、取消和生成器关闭时清理订阅。无新事件时发送心跳，连接最长 120 秒，对齐后端 110 秒规划超时。
5. POST 返回后立即显示最终方案，再读取完整回放记录，不自动重复播放动画。点击“重播地图寻路动画”可手动重播；SSE 不可用时最终方案仍正常显示。

进程内注册表最多保留 64 个 Trace。当前部署使用单 worker，内存订阅不支持多个 worker 之间共享；增加 worker 前需改用共享事件通道。已有或正在执行的搜索编号不会被新 POST 合并复用。JSON 回放优先读内存，Trace 不在内存时再读轮换日志；SSE 端点用于当前搜索，不负责恢复任意历史日志。

## 本地日志

自动规划、手动测算和地点名称搜索均生成独立 `search_id`，响应头为 `X-Search-ID`，路线结果同时返回 `search_id` 并在页面显示。日志位于项目根目录 `.runtime/search-logs/YYYY-MM-DD.jsonl`（中国时间），每行一个 JSON 事件，可按搜索编号筛选。单个文件到10MB后轮换，保留当前文件及至多3个轮换备份；按日新建文件，日志目录不提交 Git。

记录搜索输入、基准路线摘要、地图接口耗时、候选点和拒绝原因、打车淘汰依据及替代候选、最终推荐和总耗时；成功、参数错误、服务错误、超时、取消均有结束状态。地点搜索记录关键词和结果数量。不会记录地图密钥或完整地图请求 URL，完整路线轨迹不重复写入日志；候选回放会记录有数量上限的简化探索轨迹。日志写入失败会提示并继续返回规划结果。日志从功能启用后开始，不补录之前的搜索。

## 调试页候选事件回放

在 `/debug` 的“自动推荐”结果区展开“候选测试流程 · 可视化回放”，加载本次搜索，依次点击“搜索枢纽 / 出口 → 生成候选 → 名额预选 → 路线核验 → 最终推荐”。图中点位与候选列表联动，支持按名称、坐标、来源和原因筛选；点击点位查看出口约束、分流方向、近中远采样、拒绝原因及打车评分。灰色名额淘汰和预算内未完成核验不代表路线不可行。

也可以输入旧搜索编号复盘，前提是该编号对应的本地日志仍保留。回放只读本地日志，不调用地图规划接口。新搜索记录简化探索路线和出口查询范围；旧日志仅显示已有点位，不补造轨迹。调试用候选事件图不是道路地图，核验通过也不等于停靠许可。日志编号可用于读取对应行程，请仅向需要排查问题的人分享。


## 排查未推荐原因

| 日志阶段 / 字段 | 含义与排查方向 |
|---|---|
| `hub_seeds`、`hub_shortlist` | 是否召回相应枢纽，是否进入最多 10 个枢纽的接近路线查询 |
| `candidate_coarse` | 估算引擎是 `osrm` 还是 `geometry`，回退原因是什么 |
| `candidate_preselection` 的 `quota_limit` | 候选因名额限制未入选，尚不能判断路线不可行 |
| `candidate_rejected` 的 `missing_continuous_driver_route` | 未取得完整经停路线或到 P 的耗时 |
| `candidate_rejected` 的 `unusable_or_unknown_road` | P 附近道路信息不足或识别为受限路段 |
| `candidate_rejected` 的 `detour_limit` | 含停靠的司机增加时间超限 |
| `candidate_rejected` 的 `no_viable_onward_options` | 没有可保留的后续交通方案，可能涉及费用、公交接驳或数据缺失 |
| `taxi_filtered` / `transit_filtered` 的 `dominated` | 该方式被另一候选全面超过，日志关联替代候选 |
| `candidate_not_evaluated` | 提前停止或预算用尽，候选尚未完成路线判断 |

回放是日志的可视化展示，不会重新调用地图接口。自动规划日志可用于五阶段回放；手动测算和地点搜索也有编号，但不提供自动候选流程。接口按完整 32 位编号读取，没有历史行程列表；编号对应的地点、坐标和行程仍属于出行信息。


`detour_limit` 可能来自粗估剪枝或正式路线超限；`detour_bound_pruned` 也可能来自早停时对剩余候选的批量标记。候选诊断线可能回退到端点连线，不能当作实际道路或导航。详见 [算法与预算](PLANNING.md)。
